## 남은 실패 3건 (96번 중)

1. **3번 1회, 4번 1회: 판정 모델 오판.** 답변의 계획에 기대한 메뉴가 분명히 있다(3번 `미드레인지 제자리 점프슛`, 4번 `풀업 점퍼`·`스텝백 점퍼`·`드리블 풀업 3점`). 메뉴 이름 목록을 따로 줘도 가끔 틀린다. 서비스 문제가 아니라 모델 판정의 한계라서, 공식 통과 수에는 그대로 실패로 센다.
2. **9번 1회: 서비스 문제(수정함).** "나는 골대가 없어. 3점슛 연습 계획 짜줘."를 요청 해석 모델이 한 번 "다른 사용자 정보 요청"으로 잘못 분류해 거절했다(`guardrail`만 나오고 `generate_plan`이 없음). 입력 가드레일(정규식)은 통과한 질문이다.
   - 수정: 모델이 차단으로 판단하면 거절하기 전에 한 번 더 해석해서, 두 번 다 차단일 때만 거절한다. 이 수정은 2차 평가를 돌린 **뒤에** 넣은 것이라 위 93/96에는 반영되지 않았다. 수정 후 9번을 5번 따로 돌려 5/5 통과를 확인했고, 단위 테스트로 "한 번만 잘못 차단하면 거절하지 않음"과 "두 번 차단하면 거절함"을 확인했다.
   - 비용: 안전을 위해 거절 판단을 더 엄격히 바꾼 것이므로, 진짜 위반 질문도 모델이 두 번 연속 차단으로 답하지 않으면 통과할 수 있다. 다만 규칙 기반 입력 가드레일(프롬프트 유출 시도, 다른 사용자, 영상 분석, 진단, 난이도 강제)은 모델 판단과 상관없이 먼저 거절하므로 이 변경의 영향을 받지 않는다.

## 부작용과 한계

- **속도:** 골대 없이 슛이 목표인 요청(9번)은 평균 15초 -> 약 26초로 느려졌다. 목적 문구에 뺀 목표 이름이 들어가면 계획을 다시 만들게 하는 검증 때문에 재생성이 한 번 더 일어나는 것으로 보인다. 정확한 횟수는 따로 세어 보지 않았다.
- **메뉴 제외의 대가:** 골대가 없고 목표가 "슛"이면 `슛 폼 연습`처럼 장비 없이 되는 슛 메뉴도 계획에서 빠진다. 안내와 계획을 일치시키는 대신 쓸모 있는 연습 하나를 포기한 선택이다.
- **판정 모델:** 3·4번처럼 오판이 남아 있어 모델 판정 통과 수는 ±1~2건 흔들린다. 도구 호출·응답 규약은 코드 판정이라 흔들리지 않는다.
- **수정 후 전체 재측정은 하지 않았다.** 9번 오거절 수정은 9번만 다시 확인했고, 전체 96번을 다시 돌리지는 않았다.
- RAGAS는 라이브러리 없이 직접 구현한 값이라 공식 구현과 다를 수 있다.
